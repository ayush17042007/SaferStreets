## Precedence and superseded decisions (copied verbatim from master_head.md)

## 0.3 Precedence rules
1. **Part A overrides everything about visuals** (colour, type, layout, copy, components, motion). The Appendix's Section 4.1 (old palette/typography) and any colour mentions elsewhere are **superseded**.
2. **Part B overrides the Appendix on backend/infra decisions** (see 0.4).
3. The **Appendix is the source of truth** for features, user flows, roles/permissions, validation rules, database tables, endpoints and security rules, unless Part A or B explicitly changes them.
4. Appendix Section 4.5 (screen specs S1 to S33) remains the source for **behaviour, fields, buttons and states**. Part A decides how those screens **look**.
5. If something is not covered anywhere, choose the safer and simpler option and record it in the prompt as a "Decision".
