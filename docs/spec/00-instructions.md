## 0.5 Template every prompt must follow
Each prompt must be **self-contained but token-efficient**: it names which spec sections to read instead of pasting them.

```
GOAL: <one sentence: the working vertical slice this prompt delivers>
READ: <exact files/sections of this spec, e.g. "Part A2, A4, A5.3; Appendix 2A, 6 (reports tables), 7.4 (SafeRoute)">
BUILD: <numbered list: backend, frontend, tests, jobs, docs>
CONSTRAINTS: <non-negotiables: exact tokens, no mock data, honest-scope rules, security rules>
VERIFY: <commands to run + for UI prompts: Playwright screenshots at 1440x900, 768x1024, 390x844 compared against Part A; list each deviation and fix it>
DONE WHEN: <measurable criteria>
REPORT: <max 10 lines: what works, what was verified, known gaps>
```

**Mandatory rules inside every prompt**
- Work in **plan, build, verify** order. For architecture-heavy prompts (1, 7, 8, 9, 12) the agent must write a short plan first and sanity-check it before coding.
- **No mock or placeholder data in shipped code.** Real database, real endpoints. Demo data only through the seed script.
- Run typecheck, lint and tests before finishing; never report untested work as done.
- **Visual QA loop** for every UI prompt: start the app, screenshot each screen touched at the three viewports, compare to Part A, fix deviations, repeat once.
- Make small, well-named commits. Update `docs/PROGRESS.md` (max 15 lines: done / next / known issues).
- Final report max 10 lines. No restating the task, no long explanations.
- Ask questions only when truly blocked; otherwise decide and log the decision in `docs/PROGRESS.md`.
- Never claim or build: live GPS tracking, automatic police/authority integration, push notifications, payments, guaranteed emergency escalation. These are [FUTURE].
