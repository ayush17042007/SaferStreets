# PART A: DESIGN SPECIFICATION ("LAMPLIGHT")

The approved mockup was rendered inside a 680 px-wide preview, so its font and pixel sizes were scaled down. **Proportions, colours, structure and copy are binding. Pixel sizes below are the production values.**

## A1. Design principles
1. **Light, warm, calm.** Cream page, white cards, deep-ink text. No alarmism: never use red as decoration.
2. **A lit-street identity.** Streetlight **amber** is the signature highlight; **night-map panels** (deep ink with glowing lamp dots) are the hero visual.
3. **Action first.** Every screen has one obvious primary action. Quick actions sit at the top of the dashboard.
4. **Honest and reassuring.** Plain language, visible verification states, clear statements of what the product does not do.
5. **Fast to scan.** Big icon bubbles, short labels, generous whitespace, tinted status chips.

**Module colours:** SafeRoute = amber, AutoMate = mint, JourneyGuard = periwinkle, SafeAlert = coral.
**Contrast rules:** white text is allowed on `ink`, `periwinkle` and `emergency-solid`. **Never put small white text on `coral` (`#FF5A5F`) or `amber`**; use `ink` on amber. Every text/background pair must meet WCAG 2.2 AA (4.5:1 body, 3:1 large text and icons).
**Red is reserved** for emergencies and destructive actions only.

### Typography
- **Plus Jakarta Sans** for display, headings and key numbers. **Inter** for body and UI text. Load with `next/font`.
- Scale (desktop / mobile): Display **56/60 / 40/44** weight 600, letter-spacing -0.02em; H1 **32/38 / 28/34**; H2 **24/30 / 22/28**; H3 **18/24** weight 600; Body **16/24** (14/20 for dense cards on desktop); Small **14/20**; Caption **12/16** (minimum text size). Key numbers (stats, countdown) use Plus Jakarta Sans weight 600.
- Sentence case everywhere. No ALL CAPS.

### Spacing, radius, sizes
- 4 px grid. Page gutters 16 (mobile) / 24 (tablet) / 32 (desktop). Max content width 1200; landing container 1120. Card padding 16 to 20. Landing section spacing 64 to 96.
- Radius: chips 999, controls 12, cards 16, hero/ink panels 20 to 24, map cards 24, avatars 50%.
- Sizes: button 40 default (44 on mobile, **48 for hero CTAs**), input 44 (48 on mobile), icon bubble 40 (28 small), avatar 32/40, sidebar 240, top bar 64, bottom tab bar 64 plus safe-area inset. Minimum touch target 44 x 44.

### Elevation and borders
- Default cards are **flat with a 1 px `line` border**.
- Interactive card hover: border `line-control`, `translateY(-1px)`, shadow `0 6px 18px rgba(17,26,59,0.08)`.
- Floating menus/popovers: `0 12px 32px rgba(17,26,59,0.14)`. Modal overlay `rgba(17,26,59,0.5)`.
- Focus ring (all interactive elements): `2px solid #111A3B`, offset 2, plus outer `0 0 0 4px rgba(255,176,32,0.45)`.

### Motion
150 ms ease-out for hover and press; 220 ms for sheets and modals; skeleton shimmer 1.4 s; active-alert map markers pulse subtly (2 s); hero lamp glows may breathe (4 s, very subtle). **Everything respects `prefers-reduced-motion`.** No parallax, no bouncing.

### Breakpoints
360 (min supported), 768, 1024, 1280. Mobile (<768): bottom tab bar. Tablet (768 to 1023): icon-only sidebar. Desktop (>=1024): full 240 px sidebar.

## A6. Microcopy rules
- Calm, plain, warm. Sentence case. Contractions are fine. Verb-first buttons ("Start a journey", "Request to join").
- No exclamation marks on system copy. Avoid "successfully", "please", "simply", "just". No fear language ("danger zone", "crime").
- Errors: what happened, then what to do ("That code has expired. Request a new one.").
- Empty states are invitations ("All quiet around you.", "Be the first to report an issue nearby.").
- Always label unverified content "Unverified". State limits honestly: not an emergency service, no live tracking.

## A7. Accessibility
WCAG 2.2 AA; contrast rules in A2; global focus ring; full keyboard operation; semantic landmarks; labels and `aria-describedby` on forms; 44 px touch targets; `prefers-reduced-motion`; alt text for uploaded photos (fallback "Photo of {category}"); the map always has a list alternative; status never by colour alone; screen-reader pass on the five key flows.

## A8. UI fidelity contract and visual QA
- Part A is the **single visual source of truth**. Any deviation must be logged in `docs/PROGRESS.md` under "Design deviations" with a reason.
- **Tokens only:** no hard-coded hex values outside the token file; no Tailwind default palette colours in components.
- For every UI prompt, after building: run the app and take **Playwright screenshots at 1440x900, 768x1024 and 390x844** for each touched screen; check against Part A (structure, colours, radii, spacing, icon names, copy strings, states); fix; re-shoot once.
- Keep **Playwright visual-regression baselines** for the key screens (landing, dashboard, report step 1, rides, journey, alerts, auth).
- Final prompt (15) audits every screen against Part A and produces a short before/after list.
